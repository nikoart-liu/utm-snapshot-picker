# Specification: 虚拟机列表手动刷新功能 (VM List Manual Refresh)

## 1. 概述 (Overview)
当用户在外部（如 UTM 主应用）修改虚拟机名称或添加/删除虚拟机时，目前应用无法自动同步这些变化。本 Track 旨在提供一种手动触发列表刷新的机制，确保 UI 展示的数据与实际文件系统保持一致。

## 2. 功能需求 (Functional Requirements)
- **刷新按钮：** 在左侧虚拟机列表的顶部添加一个明显的“刷新”按钮。
- **重新扫描逻辑：** 点击按钮后，触发后端 Rust 函数重新扫描 `.utm` 目录。
- **数据更新：** 扫描完成后，更新前端的虚拟机列表状态。
- **选中状态处理：** 刷新操作完成后，必须清除当前已选中的虚拟机，使应用返回到未选中任何 VM 的初始状态。

## 3. 非功能需求 (Non-functional Requirements)
- **视觉反馈：** 在刷新过程中，按钮应显示加载状态或禁用，以告知用户正在处理。
- **性能：** 刷新操作不应导致界面长时间卡顿。

## 4. 验收标准 (Acceptance Criteria)
- 侧边栏顶部出现刷新按钮。
- 修改一个虚拟机的名称后，点击刷新按钮，列表能正确显示新名称。
- 点击刷新后，右侧的详细信息视图（快照列表）应被清空，左侧列表不再有选中项。

## 5. 超出范围 (Out of Scope)
- 自动文件系统监听（File System Watching）。
- 窗口获得焦点时的自动刷新逻辑。
